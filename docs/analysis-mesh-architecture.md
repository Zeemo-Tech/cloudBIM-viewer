# 构件感知分析网格架构

## 目标与边界

分析网格是 IFC 浏览模型的不可变派生表示，服务于偏差场计算和均匀着色，不替代原始 IFC/GLB。v1 的目标是：

- 不依赖“钢筋族”或圆截面放样假设，对输入三角面逐构件做各向同性重网格；
- IFC `GlobalId`、构件树、部件与渲染分片之间保持可验证映射；
- 几何与 C2M 距离场分离，改变色域、容差或连续/分段显示时不重建网格；
- 大模型按 3D Tiles 和逐分片距离文件流式加载，不把全模型合并到内存；
- 所有派生产物版本化、内容寻址、先暂存后原子发布。

原始 IFC/GLB 始终是真实来源。`analysis-mesh` 和 `analysis-c2m` 都可以删除并由输入、算法版本和参数重新生成。

## 模块边界

| 模块 | 输入 | 输出 | 责任 |
| --- | --- | --- | --- |
| `analysis_mesh.loader` | `model.glb`、`metadata.json` | `ComponentMeshStream` | 展开节点变换，以 `GlobalId` 恢复构件和原始树 |
| `analysis_mesh.adapter` | 构件流、算法参数 | 构件流 | 每个部件独立重网格，不跨构件焊接 |
| `analysis_mesh.artifact` | 构件流 | `analysis-mesh-artifact-v1` | 质量度量、分片、哈希、3D Tiles、原子发布 |
| `analysis_c2m.core` | 点云、配准矩阵、分析网格 | `analysis-c2m-result-v1` | 一次构建点云索引，逐瓦片计算距离和覆盖状态 |
| Go provider/lifecycle | 资产和算法 API | 数据库当前版本指针 | 缓存、重试、批量恢复、权限与产物验证 |
| `features/analysis-mesh` | 两种 v1 manifest | 可交互渲染会话 | 契约解析、构件显隐/聚焦、颜色模式、距离绑定 |

算法通过描述符注册，描述符包含 `id`、实现版本、契约版本、能力、参数 schema 和默认值。请求指纹包含输入内容哈希、算法实现/契约版本及有效参数，因此算法升级会生成新版本，而不会覆盖旧产物。

## 稳定契约

### `analysis-mesh-artifact-v1`

- `manifest.json`：算法身份、文件 SHA-256/大小、整体内容哈希、入口路径，以及由原始 GLB（不是重网格结果）确定的 `modelFrame`；
- `components.json`：原始 IFC 树、构件、部件、瓦片和 `positionHash`；
- `metrics.json`：源网格和分析网格的边长变异系数、三角形质量、长宽比与退化面数量；
- `tileset.json` + `tiles/*.glb`：按部件隔离的 3D Tiles；节点 extras 携带 `ifcGlobalId`、`partId`、`tileId`、`positionHash`。

`modelFrame.sourceBounds` 和 `normalizationCenter` 固定原浏览模型的坐标框架，避免重网格边界轻微漂移导致 C2M 结果与原 BIM 的居中位置不同。`positionHash` 是浏览器实际消费的 float32 顶点位置流哈希，是距离分片与几何分片绑定的主键之一。

### `analysis-c2m-result-v1`

- 每个分析网格瓦片对应一个 little-endian float32 距离文件；
- manifest 同时绑定 scan 文件哈希、analysis-mesh 内容哈希/`modelFrame`、配准矩阵、算法有效参数、瓦片 ID、部件 ID、顶点数和 `positionHash`；
- 超过覆盖阈值的顶点写为 `NaN`，前端固定显示灰色，不伪装成零偏差；
- 统计按瓦片、IFC 构件和全局分层保存。

v1 的计算覆盖阈值固定为 0.2 m，不由色带范围或容差控制。调整连续/离散模式、容差、显示色域和分区数量只在前端更新材质，不触发距离重算；已计算但超出当前显示色域的值仍保留在 `.f32` 分片中。后端把发布时的 manifest 语义快照保存在数据库中，读取版本化资源时同时核对磁盘 manifest、内容哈希、文件白名单和非符号链接路径；前端下载后还会复算距离文件 SHA-256 和 GLB 顶点位置流哈希。

## 生命周期

1. BIM 转换完成后，兼容重网格与默认 20 mm 分析网格分别进入同一有界重任务队列；分析网格直接读取原始浏览 GLB，不依赖兼容 PLY 的完成状态。
2. 服务启动时异步扫描所有已就绪 BIM，不阻塞 HTTP 启动；缓存指纹一致并通过完整契约验证则复用，否则生成新的不可变版本。
3. 分析网格发布后，后台为该 BIM 的所有历史 C2M 记录排队重算分析距离场。
4. 新 C2M 计算先返回兼容结果，同时异步生成分析距离场；前端轮询状态并优先切换到分析网格。
5. 旧 PLY 路径保留为兼容回退，不参与新契约的几何—距离绑定。

暂存目录与最终目录位于同一文件系统。Python 完成所有文件、哈希和共享组权限后原子重命名；Go 再独立验证并发布数据库当前版本指针。后台任务与同步构建 API 还共享一个可取消的 provider 闸门，确保 legacy remesh、analysis-mesh 和 analysis-c2m 不会并发挤占同一个 mesh service。

## 展示行为

- 连续模式：在负偏差—容差区—正偏差之间连续插值；
- 离散模式：在同一距离映射上量化为 2–32 个颜色分区；
- 未覆盖（`NaN`）或超出当前显示范围：灰色；改变显示范围不丢失底层距离值；
- Shift 点选：按三角形重心插值得到偏差，并显示对应 IFC `GlobalId` 与构件统计；
- 构件会话提供按 `GlobalId` 显隐和聚焦接口，流式卸载/重载后显隐状态仍保持。

## 后续算法升级

v1 生产实现为逐构件 PyMeshLab 各向同性重网格。若质量指标或性能基准不满足特定模型，可新增独立 CGAL worker，并以新的算法描述符接入同一 `ComponentMeshStream -> analysis-mesh-artifact-v1` 边界；无需修改前端、C2M 契约或资产生命周期。

建议下一阶段建立按模型类别的基准集，以源/结果边长变异系数、三角形质量 P05、Hausdorff 误差、运行时间和峰值内存作为算法准入门槛。

## 当前真实资产验收记录

2026-09-05 使用仓内现有 BIM/点云配准记录完成端到端升级验证：15 个有几何 IFC 构件生成 15 个独立瓦片，所有构件 `GlobalId` 均可在保留的树中找到；20 mm、10 轮各向同性重网格后，15 个部件的平均边长变异系数由 `0.910972` 降到 `0.422591`（平均结果/源比 `0.497722`），三角形质量 P05 平均提升 `0.327594`。历史 C2M 自动生成 15 个对应距离分片，共 30,710 个已覆盖顶点、0 个未知顶点。连续两次重启复验确认相同指纹复用不可变制品，数据库状态最终保持 `ready`。

这是一份单资产验收记录，只证明当前链路和该资产的改善，不替代上节建议的多模型基准集。
