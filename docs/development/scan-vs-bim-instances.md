# Scan-vs-BIM 逐钢筋数据链

第三步使用第二步 `denoise` 派生物中的 `cleaned.las`，其中保留源点位置、原始维度及 `cloudbim_instance_id:uint32`。`instance-map.json` 保存实例、设计拓扑单元和物理钢筋 IFC GlobalId 的对应关系；manifest 用 `instanceContract=rebar-instance-map-v1` 与 `instancesSha256` 绑定映射文件。旧版无实例关联产物需要重新执行第二步，不能回退原点云。

设计比较范围来自第二步设计钢筋目录。计算从保留 IFC 标识的 analysis-mesh 中取出相应钢筋的网格分片，排除目录以外的夹具等构件。每根物理钢筋只搜索其可靠对应实例的扫描点；可选降采样在实例内部执行，默认关闭。无拓扑单元、存在待复核对应、模型分片缺失均保留报告行并标记待复核；有设计几何但无扫描对应为缺测。

## 结果语义

- 算法：`c2m-rebar-instance-v1`；方向：`mesh-vertices-to-instance-scan-points`。
- 距离为设计钢筋网格顶点到对应实例最近扫描点的有符号距离（米），符号由模型顶点法向决定。它依赖模型网格密度、扫描覆盖和配准质量。
- 当前覆盖截断为 0.2 m；超过此距离或无可靠对应的顶点写入小端 float32 NaN，显示为灰色。
- stats 和直方图只统计有限距离。没有有效覆盖时 stats 为 null；容差内比例的分母是已覆盖顶点，覆盖率单列，不能将缺测记为合格。
- `diagnostics.rebarComparison.bars` 每行保留 IFC ID、designBarId、参与计算的 instanceIds、待复核实例、点数、覆盖、偏差统计和连续顶点区间。结果合并 PLY 和距离数组共享顶点顺序，界面筛选只改变可见三角形索引。
- 重着色使用已保存的钢筋 PLY 和原始距离，重新计算每根钢筋的容差统计。实例结果不会再触发旧的整场景最近点后台计算。

## 界面与报告

第三步保留第二步钢筋实例预览，并隐藏原点云和设计夹具。结果生成后自动加载，可按物理钢筋选择对应模型及点云。预览至多抽样 50 万个点，计算使用完整去噪实例产物（或显式启用的实例内降采样）。

可导出全部或当前钢筋 CSV，包含源资产 ID、IFC ID、实例 ID、结果版本、映射哈希、有效容差和逐筋统计。第四步报告预览附逐筋明细页，可通过浏览器打印为 PDF。未匹配/待复核项保留空偏差值；CSV 对可能被电子表格识别为公式的模型名称做转义。

输入版本包含配准、去噪版本、映射哈希、网格版本和算法标识。任一输入变化后旧结果失效；服务端同时校验逐筋顶点区间、实例唯一归属、有效覆盖计数及统计可空性。
