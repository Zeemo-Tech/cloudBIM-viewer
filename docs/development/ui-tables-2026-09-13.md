# IFC 与点云列表密度修正

用户反馈的差异来自两套工具栏换行断点、IFC 居中对齐的旧样式，以及过大的列宽。修改前表格最小宽度为 IFC 1175px、点云 1420px；1280×800 下内容区不足，右侧固定操作列掩盖了状态等字段。此前仅检查文档是否溢出，不能证明表格内容完整可见。

本次两页共用 `workspace-controls.scss` 中的 `list-surface`。统一工具栏布局、40px 表头、64px 数据行、8px 单元格左右内边距、左对齐与表格圆角；移除了 IFC 页整段重复的旧表格样式。紧缩列宽后，最小总宽度分别为 902px、916px。点云的关联模型置于文件名下方，仍显示全名提示；楼栋、构件类型、日期、状态与全部操作保留。取消固定操作列，避免遮挡字段。

实际使用项目 2 检查五组视口：2560×1440、1920×1080、1512×982、1440×900、1280×800。两页共十组检查均确认：

- 表格内容宽度不超过可视区域，每个操作按钮完整位于对应单元格内。
- 表头均左对齐且高 40px，实际数据行高 64px，无固定列覆盖。
- 文档无横向溢出；1280×800 下两页工具栏均为单行。
- 无匹配筛选、重置恢复数据、打开/关闭上传弹窗正常；最终检查无浏览器未捕获错误。
- `npm run build` 通过，保留已有大包提示；`git diff --check` 通过。

没有上传、删除、修改资产或运行分析。更小于目标桌面视口的窗口仍允许表格内部横向滚动；本次不通过隐藏业务字段或缩小字号来挤入小屏幕。
