## 检查顺序

1. **输入与实例归属**：按名称或 IFC ID 选钢筋，查看其完整扫描点与设计单元。`review` 或 `missing` 不会被强行匹配。
2. **设计网格与外法向**：读取生产 analysis-mesh 的原顶点绑定，经过同一个 `RebarSolid` 校正面绕序和外法向。
3. **连续中心线与截面**：每个点云簇独立确定位置、方向和观测范围，仅辅助采用对应设计单元的直径，联合拟合一条平滑中心轴。半径固定为设计半径；六个三次 B 样条系数表示平移、倾斜和缓慢弯曲，鲁棒径向残差与平滑约束共同优化。截面是同一条轴的采样，不再独立拟合圆或按弧覆盖拒绝。默认看整根、选择首个局部有扫描支撑的截面；“聚焦截面”进入窗口近景。蓝圆为设计，橙圆为连续轴上的设计半径圆。局部缺点标记“推断轴”，轴保持连续，表面匹配仍要求窗口内真实扫描点。
4. **扫描点径向法向**：显示求解器实际使用的 `ObservedRebarSurface` 径向向量和支撑掩码。灰点没有有效径向支撑。这里不是预处理 PCA 法向，也不是从界面保存剖面猜测的箭头。
5. **同侧对应点**：绿线连接实际接受的点对。点击设计顶点，或输入顶点索引检查；显示源扫描点索引、实例、单元、设计原法向、计算横向法向、扫描径向、三维连线长度及有符号法向分量。候选计数是最后一次查询批次的计数；各门限通过数独立统计，不可相加视为最终接受数。
6. **偏差与缺测**：向外正偏差橙色、向内负偏差蓝色、NaN 灰色。按原因筛选顶点；覆盖率和中心线等指标独立查看。

每一步是同一次计算的中间结果视图，不会因为切换显示步骤而重跑算法。箭头/连线显示有可调上限，扫描显示最多 20 万点；计算始终使用所选钢筋的完整实例点集。截面图只抽样绘制超过 2 万点的截面，轴拟合使用完整合格实例点集；只有多起点初始化最多抽取 2048 点。支持旋转、平移、缩放、俯视/侧视/端视、截图和 JSON 导出。

## 本地实验参数

- 朝向容差：1–90°；输入快照目前为 10°，产品新计算默认是 30°。
- 最大三维搜索距离：0.1–200 mm。
- 初始候选数：1–64，失败时仍按生产算法扩批。
- 中心线显示采样目标：4–128，每单元最多 64 个采样；至少保留每单元 3 点（包括两端），多单元时可超过目标。采样数量不影响整根轴的优化。
- 截面窗口倍率：0.25–4，默认 1。控制局部证据显示和同侧匹配的轴向范围；不改变轴拟合。默认窗口沿用原单单元 16 截面的尺度。
- 最小弧覆盖参数仅保留历史 JSON 兼容，界面隐藏；新拟合不使用逐截面的弧覆盖门限。近乎单条母线、整段点数/自身轴向范围不足或与设计半径不一致时，拒绝该簇并提供原因。设计位置、方向、长度和 200 mm 表面搜索距离不参与轴拟合准入。

“恢复输入参数”恢复本快照的参数；参数修改后必须重新运行。可将一个批次“设为对照”，对比有效顶点数、逐点偏差及中心线（紫色）；跨钢筋时不比较。历史下拉加载完整独立调试批次。JSON 包括完整点、网格、原点、真实法向、点索引、剖面、拒绝原因、参数和输入来源。

### 钢筋切换与结果复用

选择钢筋、上一根／下一根和页面初始化会优先复用当前输入版本下该钢筋、全部参数完全一致的最新批次。未找到时才计算；“重新运行当前钢筋”始终强制计算，并替换后续自动复用的批次。改参数不会借用其他参数的结果。

浏览器最多在内存中保留最近 3 个完整 JSON 结果；切回时无需再次下载或解析。不可变结果文件使用 gzip 无损压缩和浏览器持久缓存，内存淘汰后可从浏览器缓存恢复，避免重复传输数十 MB 的 JSON。实时目录、状态和页面代码仍禁止缓存。

当前钢筋显示后，低优先级预取相邻钢筋已经完成的同参数结果（最多两个在途加载）；切换时复用正在加载的请求。预取不会触发计算，后台失败也不影响当前画面。

兼容字段 `sessionId` 现为 SHA-256 输入版本标识：覆盖完整扫描、映射、分析网格文件内容、配准和默认参数、数值计算 Python 源码及依赖版本。相同输入的服务重启保留有效结果；修改数据、算法或依赖后才失效。历史接口保留最近 100 批次，并额外保留当前版本每个钢筋／参数组合的最新批次，避免默认结果被大量实验挤出。

可提前准备固定快照所有钢筋的默认结果。以下是离线计算工具，不启动服务或占用网页的前台计算任务；已有有效默认结果会跳过，结束时再次校验输入版本未变化。准备完成后，用标准开发管理器启动／重启练武场即可复用：

```bash
.cloudbim/mesh-venv/bin/python scripts/scan-bim-debug.py --inputs .cloudbim/scan-bim-workbench/inputs.json --prepare-defaults
```

切换场景时先更新几何、图层和相机，最后统一绘制，避免用上一根钢筋的相机连续渲染中间状态。计算请求通过 `requestId` 关联不可变批次；其他浏览器更新全局运行状态时，当前页面仍加载自己的结果。

切换回归：`node scripts/test_scan_bim_switch_cache.mjs`。使用真实服务验证同参数切回小于 1 秒、不重算、不重复下载，参数隔离、显式重算、内存淘汰后文件复用、页面刷新复用、并行浏览器的结果归属，以及输入版本变化后失效。`scripts/test_scan_bim_debug.py` 验证传输解压后逐字节一致、缓存响应头、版本变更失效、重启复用、批次保留和重复预计算跳过。

## 逐簇独立拟合与腹杆分段验收（2026-09-13）

当前算法标识：`scan-bim-independent-clusters-v1`，轴方法为 `scan-cluster-independent-axis-v1`。设计位置、方向和长度不传入求解器。每簇自身 PCA 坐标作为数值参数化，全部有限实例点参与鲁棒已知半径拟合；半径仍辅助采用设计值，未声称实测直径。观测跨度取径向内点轴向 0.5%–99.5% 分位数，不等于实体总长度，也不强制等于设计长度。样条仅惩罚弯曲，不惩罚平移或倾斜。局部无点处的推断轴使用虚线，不生成表面对应点。

腹杆输入已经具有 36 个解析直段与分簇归属。练武场现在按相同单元 ID 将原网格三角面划分成 36 份；每面仅属于一份、全部原始顶点和面索引保留，弯角面按最近有限设计段分组。JSON 提供 `mesh.parts`、逐面 `faceUnitIds`、逐顶点 `unitIds`。缺少扫描簇的设计段仍保留，显示“无点云簇”。不改写 IFC 或正式分析网格。

页面左侧 **设计段 ↔ 点云簇** 可单独选择每段，设计网格、扫描点、中心轴、法向和截面目录同步筛选。输入/设计步骤按同一段与簇分色；可关闭设计图层后点“适配”，独立查看放偏的实测轴。单段信息展示簇 ID、点数、设计长度、观测跨度和拟合残差。`measurement.clusterFits` 明示位置/长度/方向均未约束。

真实验收对象：短筋 555867、555928、555987、555999，以及腹杆 558730、558894、559236、559237。四根短筋均生成 64/64 轴采样，最大横向轴偏移约为 202.79、202.65、205.75、223.83 mm。它们属于当前快照的算法输出，未经独立实测标定；不再因为偏移大或长度不同就拒绝拟合。表面对应仍受页面搜索距离约束，因此有轴而部分表面缺测是允许的。555867 的输入实例还包含与主要扫描段分离的一小段点，观测跨度包括该间隔；虚线和“局部有扫描支撑”计数用于区别推断与真实局部证据。

验证：84 项 Python 定向回归、4 项 HTTP 边界测试；原练武场 UI 测试覆盖真实顶点索引、窗口改参不改变轴、对照和多尺寸布局；`node scripts/test_scan_bim_cluster_ui.mjs` 检查上述八根真实钢筋，验证完整网格分组无丢面/重复面、同段对应点索引和逐段界面筛选。证据在 `.cloudbim/scan-bim-independent-clusters/ui/`，批次保存在练武场历史中。服务通过 `scan-bim-stop` / `scan-bim-start` 重启，仅 8767 启用新算法。

## 下一根钢筋切换性能（2026-09-13）

## 直线段切换主线程开销（2026-09-14）

进一步区分“换整根”和“同筋换直段”后，发现原有往返换筋小于 1 秒的回归不足以覆盖流畅性：同筋切段没有网络或算法请求，但每次仍给整根网格和扫描重新着色，遍历整根面/点做筛选，并再次遍历全部点计算相机范围。真实 36 段腹杆 `2o97Tbskf2JPl1QtzNqS0X` 连续 12 次切段，1920×1080 Chromium/SwiftShader 下，点击处理平均约 22.0 ms；4 倍 CPU 降速下约 115.7 ms。

现在加载钢筋时建立扫描点、设计顶点和三角面的逐段索引，切段只访问当前段；颜色按步骤及是否整根分色复用，仅颜色语义变化时上传。截面投影同样只遍历所属点，保留未分配点的历史回退行为。原全局点/顶点索引、面归属和数值结果不变。同一测量脚本下点击处理平均约 2.6 ms；4 倍降速约 7.6 ms。此处是主线程点击处理耗时，不是网络首次加载或用户设备上的端到端延迟。

回归：`node scripts/test_scan_bim_segment_performance.mjs`，真实连续切段检查完整三角面/扫描点索引一致、颜色缓冲版本不变、无计算请求，并要求 4 倍 CPU 降速下点击处理 P90 小于 50 ms。另通过 `test_scan_bim_segment_navigation.mjs`（六个步骤、截面、点选、统计、移动端）及 `test_scan_bim_render_performance.mjs`（轴批次、虚线、联合筛选、换整根材质复用）。

## 换整根钢筋：默认结果缺失与缓存失效（2026-09-14）

本次继续验证“上一根／下一根”，而非只测同筋切段。发现当前服务的 70 根钢筋仅有 10 根匹配当前输入版本及默认参数的结果；连续进入未准备的钢筋时，浏览器实际发出 `/api/run`，等待约 1.6–3.6 秒。已有 JSON 缓存的往返测试无法覆盖这一问题。

旧版本标识递归包含 mesh-service 全部非测试 Python 文件，导致独立去噪实验代码变化也使固定扫描快照的比较结果失效。标识现升级为 v3：从 `rebar_workbench.py` 跟踪本地绝对、相对及函数内导入，保留依赖模块、包初始化文件、输入文件完整内容和依赖版本；动态导入保守退回全部 Python 文件。`algorithms/__init__.py` 本身仍纳入哈希，但其中仅注册到独立去噪注册表的实现不沿注册关系加入；比较器直接导入使用的数值模块正常跟踪。这一例外基于练武场不调用去噪注册表的当前架构。输入扫描、映射、配准或实际比较依赖变化仍使旧结果失效。

完成 v3 版本全部 70 根默认结果的离线准备，并通过开发管理器重启 8767 服务，核验运行服务标识与当前磁盘依赖一致。相邻结果预取移除原 250 ms 延迟，在当前场景完成后立即调度，仍不触发计算。未缓存结果的完整 JSON 下载及解析仍有实际开销；没有通过丢弃诊断数据换取速度。

新增 `node scripts/test_scan_bim_bar_navigation.mjs`：先断言目录每一根都有匹配版本及默认参数的结果，再从第一根连续访问全部 70 根；主动阻止 `/api/run`，确保不能通过测试时现场补算掩盖缺失。服务重启后的本机 Chromium、1920×1080、SwiftShader 测量：69 次换筋平均 52.7 ms、P95 103.0 ms、最大 108.6 ms，计算请求 0；包含加载等待和随后一帧，不是用户设备／远程网络时延保证。结果保存在 `.cloudbim/bar-navigation-performance/journey.json`。

HTTP/缓存依赖验证：`.cloudbim/mesh-venv/bin/python scripts/test_scan_bim_debug.py`，9 项通过，涵盖实际数值依赖与输入字节失效、无关去噪排除、递归相对/延迟导入、动态导入保守回退、版本重启复用、参数校验和压缩传输。

## 开场完整加载全部钢筋（2026-09-14，替代三根缓存与相邻预取）

按用户要求，进入页面时先准备当前参数下所有钢筋的结果，再以两个并发下载任务加载并解析完整 JSON，最后逐根建立段索引、颜色、三维几何与 GPU 缓冲。开场进度依次显示准备结果、加载数据、准备三维显示；全部完成后才开放查看，并恢复 URL 指定的钢筋。缺失结果在此阶段计算，下载或准备失败保留进度页并提供重试，不把不完整加载误报为成功。

完整快照的所有结果固定保留在浏览器内存，三维对象也随结果复用；不再受原三根缓存上限约束。同参数换筋不查询目录、不下载 JSON、不重新建立整根三维对象。额外参数或历史版本仍使用小型缓存；明确重新计算的结果替换相同钢筋和参数的固定缓存项。点/面全局索引、截面过滤及数值结果保持原样。

已打开页面按加载时的完整快照查看，允许断网浏览。服务输入更新或希望同步其他页面的结果时，使用“重新加载全部”或刷新页面；重新加载会读取当前版本、释放失效几何、准备所选参数的全部结果。此行为替代旧版每次切筋都联网校验版本的方式。

验收：`node scripts/test_scan_bim_preload_all.mjs`，本机 1920×1080 Chromium/SwiftShader 首次完整加载 70 根约 3.24 秒；之后断网、4 倍 CPU 降速、交替选择远处钢筋遍历全部 70 根，网络请求 0，切换处理平均约 23.8 ms、P95 40.2 ms。时间受设备与网络影响。此模式以常驻全部数据换取切换流畅；验收进程 JS 堆使用量约 471 MiB（包含切换中的临时分配，不是整个浏览器内存）。检查结果与截图位于 `.cloudbim/preload-all/`。
