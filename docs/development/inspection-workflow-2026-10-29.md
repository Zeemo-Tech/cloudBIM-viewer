# 巡检入口、自动偏差计算与侧栏精简

2026-10-29，`dev-hong`。分析工作区已支持双击钢筋直接巡检、左侧自动轮播、分类后自动计算偏差，以及报告默认 100% 缩放。

## 页面行为

| 操作 | 当前行为 |
| --- | --- |
| 第三步双击钢筋 | 选中并平滑定位这一根，无需先开启模式 |
| Esc / 双击模型空白处 | 退出巡检，恢复整体着色和材质 |
| 左侧“自动巡检”按钮 | 按既有空间顺序每 3 秒切换，末尾回到第一根；再次点击退出 |
| 巡检中单击 / Alt + 单击 | 选择鼠标下的钢筋 / 沿深度切换重叠钢筋，保留视角 |
| 拖动、滚轮、切换视角、失焦、切换步骤 | 停止自动轮播或未完成的取景动画，交还相机控制 |
| 报告首次打开 | 100%；仍可调整比例或使用“适应页面” |

第三步右栏只有“偏差计算”和“配色调整”。巡检信息压缩为视口内的序号和名称；历史计算批次与 JSON/CSV 导出归入报告。第一步保留配准操作和一行手柄快捷键；第二步保留处理、结果数量、配色与类别；报告栏移除未实现的格式/发布按钮和重复状态，保留导出前保存编辑的必要提醒。开发调试面板仍由显式调试入口控制。

## 默认计算及复用

第二步原本已经生成柔性控制网、实例对应和观测证据；第三步仍需在设计网格顶点上计算同侧表面偏差、汇总逐筋测量和生成着色产物。现在分类完成后自动衔接该阶段，使用当前保存配准、去噪版本和分析网格，不再要求再点一次“计算”。

- 页面进入第二步及后续步骤时先读取最新结果，服务端确认 `fresh=true` 则直接复用。
- 输入版本变化或重新分类完成后，缺失/过期结果自动计算一次；网格仍在处理中则等待其就绪。
- 并发读取合并为一个 Promise；计算中不再读取旧结果并使当前请求失效。
- 读取失败与结果不存在分开处理。网络/计算失败显示状态并保留手动重试，不循环重算。
- 默认不降采样，沿用 30° 同侧法向约束、0.2 m 搜索范围及既有控制网算法。

自动衔接由分析页面负责。关闭页面后的独立后台流水线不在本次实现范围内。

## 性能与结果一致性

计算层按钢筋独立并发，默认 4 线程；实例归属一次稳定分组，结果仍按原顺序合并。详细固定输入实验见 [Scan-vs-BIM 加速记录](../research/scan-bim-performance-2026-10-29.md)。

| 固定输入 | 原计算中位数 | 当前计算中位数 | 降低 |
| --- | --- | --- | --- |
| scan14 / BIM13 | 9.208 s | 4.726 s | 48.7% |
| scan5 / BIM7 | 11.680 s | 5.442 s | 53.4% |

此表是完整 Python 计算函数的 wall-clock，未包含 HTTP 和浏览器。完整距离、NaN 掩码、网格、归属和测量逐项相同，仅排除计时。8 线程没有稳定收益，且内存更高。

在托管本地栈上完成两次实际“分类 → 自动偏差计算”：分类 HTTP 分别为 79.084 / 64.999 s，随后的 C2M HTTP 为 **7.990 / 8.015 s**，其中计算层 `total` 为 **5.413 / 5.492 s**。这些是单机运行样本，浏览器 SwiftShader 同时占用 CPU，不能用来替代上表的固定输入基准。

为了验证“没有可用结果”分支且保留已存历史，每次仅拦截分类完成后的一个 latest GET 为 404；分类 POST、偏差 POST、结果下载及刷新均走真实后端。每次恰好一个分类请求、一个自动比较请求，重新打开页面不再次计算。去噪接口每次发布新的随机版本目录；它不是缓存命中接口。

两次后置校验最初误把版本当成可复用键、把 latest artifact URL 当成历史 URL，断言失败；业务请求已成功完成。校验随后按现有接口合同修正，通过只读恢复模式验证第二次运行，未为修复校验再次计算。历史报告通过 report API 校验，历史去噪文件通过本地不可变目录校验。

最终去噪版本 `5738627a95ef330e99f8304e`。保存配准不变；初始版本 `903d8138e664cb81a2fe9aa0` 的实例映射和控制网 SHA256 未变，初始历史报告内容逐项一致。最终完整距离二进制与初始结果 SHA256 同为 `dc6b90e9d50ddcf4eaaf74e12848452b1682c962c3463408be09734e5bc950df`；逐筋测量/检验全部相同，只排除计时及已独立验证的版本哈希。历史报告不等同于历史几何下载，latest 距离接口仍只接受当前版本。
