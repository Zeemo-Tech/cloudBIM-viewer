# 控制网接入生产分割与逐筋检测

2026-09-15。工作分支 `dev-hong`。本次沿用现有页面流程和设计网格偏差配色。

## 入口与数据流

1. 保存点云与 BIM 配准。
2. 在第二步执行“钢筋实例分割与去噪”。生产入口运行法向与台面处理，随后直接调用现有最新 `fit_control_net(mode='aligned')`，不再先走完整几何分类和拓扑重新分配。
3. 在第三步计算偏差。带有控制网证据的新结果使用控制曲线组织局部同侧方向与真实扫描点对应；生成的仍是设计钢筋网格顶点距离数组和着色 PLY。
4. 展开“钢筋间距”查看可确认分组的中心距。设计模型颜色继续表示表面偏差，间距是独立测量，不能把两种数字混用。
5. 第三步或报告页导出“已保存检测 JSON”。历史计算批次也可导出。前端尚未保存的容差预览不会改写历史 JSON；先保存配色设置，再导出对应新批次。

旧的生产分割产物缺少控制网证据，升级后需要重新执行第二步和第三步。历史报告仍可阅读，缺少新指标的旧批次不会伪造间距结果。

## 产物

### 实例分割

- `cleaned.las`：可靠匹配钢筋的原始记录；保留原始坐标和维度，附 `cloudbim_instance_id:uint32`。
- `preview.ply`：全源采样预览，保留分类与实例号。待定点在这里可见，不因偏离设计直接判为噪声。
- `instance-map.json`：保持 `rebar-instance-map-v1`，完整保存物理母筋、设计单元及实例对应；新增 `controlNet`。
- `control-net.json`：`rebar-control-net-evidence-v1`，与实例映射中同名内容一致，含算法版本、坐标系及完整拟合报告。
- `manifest.json`：绑定源扫描、设计指纹、实例映射哈希、控制网哈希和算法版本。

控制网坐标为 `scan`，设计目录也已经通过保存的配准转换到扫描坐标。下游仅应用一次实际请求的 scan→BIM 矩阵。该矩阵按列主序保存，距离单位为米。

主体状态映射为 `fitted→matched`、`pending→ambiguous`、`missing→missing`。缺测直段不应使同一母筋其他可信直段丧失可计算性；身份歧义继续保留复核约束。

### 检测数据

`diagnostics.rebarComparison.inspection` 使用 `rebar-inspection-v1`。机器可读定义见 [JSON Schema](../schemas/rebar-inspection-v1.schema.json)。这是本项目的版本化数据契约，并非外部工程验收标准。

主要字段：

| 字段 | 内容 |
| --- | --- |
| `coordinateFrame / lengthUnit` | BIM 坐标、米 |
| `method / provenance` | 测量方法、控制网版本、实例映射哈希、实际配准矩阵 |
| `bars` | 物理钢筋 ID、IFC ID、观测支持的曲线区间、覆盖与表面统计 |
| `spacing` | 设计相邻组、间距方向、逐站中心距及相对设计差值、缺测状态 |
| `summary` | 各类支持/缺测计数和实际使用的容差来源 |

未知量使用 JSON `null`。二进制顶点距离继续使用 NaN 表示未知，设计网格显示灰色；不能把 NaN 原样写成 JSON 数值。

下载入口：`GET /alignments/bim/c2m/reports/:version/json`。结果来自服务端保存的快照，包含检测数据和报告所需的来源/参数信息，受既有用户权限限制。与浏览器本地 PDF/CSV 导出不同，它不依赖当前屏幕筛选，保留整个批次。

## 测量范围和限制

- 控制曲线用于判断同侧、局部方向和中心位置。表面距离仍来自真实扫描点，不生成不可见背面的假扫描点。
- 设计推断的曲线不能整段充当观测；具有独立局部支持的区间可以单独使用，缺口继续未知。
- 间距首版检查有明确同层、同方向/分组关系的相邻钢筋；在共同覆盖的检查站测中心距。不会把任意空间最近筋当作检查邻居。
- 工程容差沿用请求中的 `toleranceLimit`，JSON 明确记录 `toleranceBasis=request.toleranceLimit`，不冒充规范阈值。
- 以设计半径换算的净距标明 `radiusSource=design-prior`。本次没有实现独立规格认证，固定设计半径的拟合不能证明现场用了正确直径。
- 曲线支持和空间归属仍受上游拟合质量影响。真实运行计数与拟合残差不等于人工真值精度。
