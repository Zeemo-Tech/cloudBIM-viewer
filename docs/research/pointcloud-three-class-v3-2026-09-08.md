# 第 2 步：台面、钢筋、夹具三分类

后续增加钢筋末端和交叉处补回，见 [v4 说明](pointcloud-rebar-recovery-v4-2026-09-08.md)。三类定义保持一致。

2026-09-08，`normal-geometry-v3`。本版本按用户明确修正的场景定义实现，取代此前将
“夹具”限制为“达到平面面积条件的点”、将其余点保留待定的方案。

## 当前规则

1. 识别台面。
2. 识别细长、圆截面法向量分布的钢筋。
3. 其余点统一归夹具。方管的侧面、圆角、边缘、夹具接触处不输出子类别，也不退回待定。

局部平面只用于定位可靠的夹具支撑位置、避免将方管边缘错当成钢筋。
以支撑位置附近 6 mm 空间作为同一夹具的一部分，覆盖边缘时不再检查该点是否平面。
小面积表面和没有有效法向量的点也有三类归属：继承已识别网格的类别，否则归夹具。
钢筋和夹具接触处允许粗略归属，不设置独立保护带。

输出 `geometry_class` 只有 `1=台面、2=夹具、3=钢筋`，元数据同样只列这三类。
旧历史结果的类别 0 只在打开旧记录时显示，当前运行不生成类别 0。
源 LAS 的标准 `classification` 字段保留，新结果仍保存在独立附加字段及 NPY 中。

这一规则使用了当前场景“台面和钢筋之外基本是夹具”的先验。未识别到的钢筋、杂点也会
进入夹具类；本轮不增加去噪或钢筋实例补全步骤，不用“没有待定”声称分类准确率。

## 实现与效率

实现：`services/mesh-service/algorithms/normal_geometry_classifier.py`。
保留批量特征计算、有界并行邻域查询，缓存原始 KD 树、残余支撑树、夹具支撑树、网格索引映射和中间特征。
新增夹具归属树用于直接分配侧面附近的圆角 / 边缘，并让这些点跳过圆截面计算。

每次调试运行仍从原始文件读取、校验、计算第 1 步法向量，再执行第 2 步分类。
全量源文件为 9,216,369 点，k=32，16 线程。首轮分类 3.788 s、全流程 11.929 s；
第二轮分类 4.082 s、全流程 12.313 s，两轮逐点分类一致。浏览器预览仅抽样显示，计算和保存均覆盖全部源点。
交付核验运行 `20260908T084956-2134d82a`：法向量 4.961 s、分类 3.917 s、全流程 12.113 s，
分类约 235 万点 / 秒；与前两轮逐点标签一致。耗时不含浏览器加载与渲染，未清理系统文件缓存。
该轮完整记录和输出位置见 `.cloudbim/pointcloud-debug/three-class-final.json`。
