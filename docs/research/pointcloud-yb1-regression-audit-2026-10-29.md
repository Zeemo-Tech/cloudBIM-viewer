# YB-1 钢筋分类与耗时回归审查

2026-10-29；`hong-pc` 本地开发环境；`dev-hong`，审查时 HEAD `b32b61a2d7700314cce993223a2eac288fe9935b`。对象为点云 **5 / BIM 7**（YB-1 第一代数据）。本轮完成原因审查、逐源行核对和隔离反事实回放，**没有修改业务算法、数据库/latest、保存配准或原始资产**。

结论：这份老数据确实出现了分类覆盖和性能回归。主要原因是原有控制网拟合之后，又对所有符合长度条件的直筋执行一轮额外柔性轴线拟合；这轮拟合可以用局部通过验证的新模型替换整根旧模型及点归属，却没有检查旧模型已解释的其余扫描区域是否退化。针对双层场景增加的流程进入了单层旧数据，但先前验收没有覆盖这种跨数据集回归。

## 2. 最明确的局部回归：实例 9 的末段消失

该设计段长 4.166 m。旧版观测长度约 **3.939 m**，当前只有 **2.808 m**，当前认可区间为 `[0, 0.200]`、`[0.256, 2.864]` m。实例点数从 **66,325** 降到 **48,191**，其中 **18,325** 个旧钢筋点变成未分类。

当前截面追踪选择了 `0–2.832 m` 的 232 个截面。`_fit_ifc_axis` 仅从这条选中轨迹的源行中划分训练和留出数据，所以新模型可以获得 **99.9528%** 留出支持率，同时没有解释旧模型已经解释的后段。随后 `recover_bent_bars` 将旧归属中不在新支持集内的点置为 `owner=0 / status=2`，发布时映射成未分类。

这是**局部验证分母没有覆盖模型替换影响范围**的问题。局部残差很好，不能代替对整根既有支持的比较。

在设计轴向 **3.0–4.0 m** 的固定区域，取旧版归属于实例 9、旧管面残差不超过 1.44 mm 的全部 **14,476** 个源点。选择条件不依赖新标签：

| 固定区域回归探针 | 当前完整分类 | 仅跳过新增长筋复核 |
| --- | ---: | ---: |
| 保持实例 9 的比例 | **0%** | **100%** |
| 未分类点 | **14,476** | **0** |
| 至少保留 95% 的诊断门槛 | FAIL | PASS |

探针在当前结果上实际失败，在反事实结果上通过。95% 是本次固定区域的回归验收线，不是现场精度标准，也不把旧标签当作全场景人工真值。

## 3. 为什么贴近钢筋的点仍然未分类

当前点归属同时要求：距拟合管面足够近、法向相容、位于已认可的轴向支持区间。8 mm 直径钢筋的该阶段管面容差为 **1.4 mm**，法向径向一致性要求大于 **0.65**。认可区间还依赖局部点数、径向/法向分布、空间留出支持、邻筋身份和片段连接检查。

本次对落在已更新柔性主体上的 **47,552** 个旧钢筋→未分类点，用保存的 B 样条参数重建当前模型并逐点复核。按“先距离、再法向、最后区间”排列的互斥归因为：

| 当前判定不通过的首个条件 | 点数 |
| --- | ---: |
| 管面距离 | 29,755 |
| 距离通过，法向不通过 | 11,717 |
| 距离和法向均通过，仅不在认可区间 | **6,080** |
| 三项均通过但仍未分类 | 0 |

其中 **14,350** 个点距当前拟合管面不超过 1 mm，**27,611** 个不超过 2 mm。因此用户观察到的近表面未分类确实存在。比如源行 `1584487` 距当前实例 9 管面约 **0.133 mm**、法向一致性 **0.996**，仅因为轴向位置 `0.200438 m` 位于认可区间边界之外而未分类。

这些统计解释算法如何拒绝点，并不证明所有拒绝都错误。法向冲突、真实缺测和相邻构件本来就可能要求保留未分类。剩余 **1,492** 个旧钢筋→未分类点未纳入上表的柔性主体分解，其具体末端/弯钩判定未逐项拆解；全流程反事实已将总变化归因于新增主体复核及它对后续依赖几何的影响。

证据：[当前模型逐点复核](../development/assets/yb1-regression-2026-10-29/surface-audit.json)。门槛位于 `bim_bent_bars.py:599,641–653`，局部区间验证位于 `:417–585`。

## 4. 耗时为什么从约 27 秒变成一分钟

旧版 v24 本来已有柔性控制网、局部弯曲/末端修正。当前仍先运行这套控制网，然后额外运行截面追踪和四种候选轴线求解。额外复核没有以“原拟合是否存在缺口或局部质量问题”为触发条件。

YB-1 本次有 **54** 个直筋段进入额外复核，**52** 个发布了修订。该输入只解析到 **1** 个非钢筋场景对象，场景分类没有认领夹具、预埋件或管道点；大量时间并非花在复杂夹具上。

使用项目 Python 3.11 环境、8 个工作进程，顺序执行同一分类函数的两个隔离回放。当前回放的 **3,900,373 行类别、钢筋实例和场景实例**与当前正式保存结果的差异全部为 **0**。

| 相同输入的分类函数回放 | 当前 | 仅跳过新增长筋复核 |
| --- | ---: | ---: |
| 全部分类阶段 | **61.25 s** | **18.93 s** |
| 其中新增长筋复核 | **41.60 s** | 0.001 s 包装开销 |
| 原控制网阶段 | 9.68 s | 9.65 s |
| 弯钩阶段 | 6.20 s | 5.55 s |
| 最终钢筋点 | 1,818,971 | **1,836,753** |
| 相对 v24 释放旧钢筋点 | 49,044 | **0** |
| 相对 v24 新增钢筋点 | 31,268 | **6** |
| v24 原钢筋实例归属变化 | — | **0** |

该消融仅在独立 Python 进程中替换阶段调用，没有改工作区算法，没有向业务接口发布结果。两边都重新运行其余所有分类阶段。61.25/18.93 s **不包括输入/模型读取、预处理和产物导出**；历史 27.28 s 与当前 65–73 s 来自完整 manifest。两种时间口径分别列出，不能将 18.93 s 宣称为修复后的完整接口时间。这是一组同机配对观测，不是多轮统计结论。

直接新增主体阶段释放 **45,886** 点、加入 **32,810** 点；后续弯钩和端面依赖新的主体，最终相对历史版本产生前述 49,044/31,268 变化。关闭它能恢复历史标签和实例，说明主要回归来自这条新增路径，而非导出或页面显示。

证据：[当前回放](../development/assets/yb1-regression-2026-10-29/current-replay.json)、[单阶段消融](../development/assets/yb1-regression-2026-10-29/without-extra-bent-replay.json)、[逐阶段归属](../development/assets/yb1-regression-2026-10-29/stage-comparison.json)。

## 6. 修复优先级与可复用验收

1. **给模型替换增加同域比较。** 新旧模型必须在同一批固定源点、相同空间窗口上比较；新模型的局部留出高分不能授权删除未经比较的旧有效末段。旧点若确实偏离模型或属于邻筋仍应释放，不能把无条件合并旧归属作为修复。
2. **恢复按需复核。** 对原控制网已解释充分的主体保留快速路径；有明确局部残差、缺口或偏移证据才进入额外截面和多模型求解。先保护 YB-1 已验证区域，同时继续保留双层数据所需的恢复能力。
3. **分开检查局部发现失败和点面证据失败。** 对距已验证模型很近、法向相容却仅在区间边界外的点，用原始局部观测复核其连续支持，继续保留邻筋、平面和缺测约束。
4. **同时验收两份数据。** 固定点云5/BIM7与点云14/BIM13，检查已知区域覆盖、跨实例变化、最终模型/点归属一致性和源记录保留。第一代数据完整入口恢复至30秒以内可作为性能目标；本次18.93秒的函数消融尚不能充当该目标已完成的证据。
