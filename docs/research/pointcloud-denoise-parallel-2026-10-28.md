# 双层钢筋并行调度复测（2026-10-28）

在上一轮 `execution-v3` 基础上，进一步改为跨钢筋提前计算截面，并复用一次请求内的拟合进程池。本地 HTTP 完整请求从 **73.61 秒降至 63.75 秒**（首次模型解析）、从 **63.50 秒降至 53.77 秒**（模型缓存命中）；全部扫描拟合与分类仍重新执行。完整主机调用为 **52.51 秒**。30 秒目标仍未达到。输入仍为 Lumos 扫描 14 / BIM 13、同一份保存配准及 4,038,141 个源点，所有实验另存目录。

## 并行为何没有充分起效

原版本已有 8 个进程，但每根筋都先等待截面计算完成，再等待四个轴线模型完成，之后才开始下一根筋。轴线模型的计算量不均，完成较早的进程会闲置。固定真实长筋阶段的隔离回放测得平均 CPU 利用为 3.85 核。

本轮保持工作进程数不变：当前筋的四个轴线模型提交后，父进程准备下一根筋的截面，并将这些局部任务提交到同一进程池。前一根筋确认归属后，逐截面检查候选源行是否被占用；仅对发生变化的截面重新计算，之后再执行下一根筋的最终拟合。相邻筋的源行竞争仍按原设计顺序处理。

## 固定长筋输入的对照

以下只测 `recover_bent_bars`，不冒充完整去噪请求。CPU 核数为本调用父进程与已退出子进程的 CPU 时间之和除以墙钟时间。进程启动消耗计入；每个进程中的 BLAS 数值线程限制为 1。

| 方案 | 进程数 | 长筋阶段 / 秒 | 平均使用 CPU 核 | 与原报告及逐点归属比较 |
|---|---:|---:|---:|---|
| 原有逐根等待 | 8 | 28.20 | 3.85 | 基准 |
| 合并小任务、连续填充队列 | 8 | 27.07 | 3.85 | 完全一致 |
| 另加下一根截面提前计算 | 8 | **19.86** | **5.37** | 完全一致 |
| 同样提前计算，增加进程 | 16 | 20.49 | 7.65 | 完全一致 |

8 进程提前计算相较原调度缩短 **29.6%**。16 进程消耗更多 CPU 时间且墙钟略慢，本机保留 8 进程；没有将进程数翻倍当作加速证据。这些是单次固定输入对照，未构成多机或并发负载下的统计基准。

## 完整调用与服务验证

本轮开始时重新运行旧调度的完整构建，模型缓存未命中，为 72.58 秒。最终主机完整构建为 **52.51 秒**，模型缓存命中；两者缓存条件不同，不能将全部差值归因于并行。下表以同一 HTTP 入口、分别匹配缓存条件比较。

| 完整 HTTP 请求 | 上轮 `execution-v3` / 秒 | 本轮 `execution-v4` / 秒 | 缩短 |
|---|---:|---:|---:|
| 首次模型解析，三项模型缓存均未命中 | 73.61 | **63.75** | 13.4% |
| 三项模型缓存命中，所有扫描计算重做 | 63.50 | **53.77** | 15.3% |

两次请求均返回 HTTP 200，容器实际配置为 8 个工作进程，版本为 `execution-v4`，原生几何内核已启用。长筋柔性轴线阶段为 19.73–19.77 秒，弯钩复核为 7.63–7.64 秒。两个服务结果均完成全量源行和导出属性对照，类别、钢筋实例、场景实例均无差异。新调度同时缩短冷、热请求，收益约 10 秒。

工作池由一次 `fit_bim_guided_scene` 请求统一创建，控制网、初次弯钩、柔性轴线和弯钩复核共享同一池。独立使用这些模块仍可自行管理进程池；传入外部池时不得关闭它。流程版本为 `execution-v4`。

## 正确性与保存范围

- 本轮 **105 项相关 Python 回归测试通过**，涵盖弯筋、控制网、逐步归属、弯钩、端部参数及完整去噪入口。新增测试专门覆盖：已经排队的截面在点归属改变后重算、尚未排队的窗口读取最新点范围、外部进程池保持可用，以及错误预算配置被拒绝。
- 完整主机输出与修改前 332.99 秒的独立基准比较：`classes`、`instances`、`sceneInstances` 均为 **0 个源行差异**。全部导出 LAS 源维度与相应原始记录一致，设计目录及完整配准指纹验证通过。
- 新旧调度的完整主机 `control-net.json`、`scene-classification.json` 除耗时和缓存状态外完全一致；轴线、曲线、证据、确认状态和数量没有变化。
- 预计算只保存当前/下一根筋的局部数组与有界任务，不缓存扫描最终结果；每次请求重新拟合和分类。待修正任务数量受预计算窗口约束，不随整个扫描长度无限增长。
- 输出保存在独立实验目录，不发布业务 derivative，不替换用户原始数据、保存配准或历史结果。部署及复测后，58 个关键文件的 SHA256 全部不变，数据库保存配准与 denoise derivative 记录也未改变，详见 `preservation-final.json`。服务耗时不包括浏览器绘制完成时间。
