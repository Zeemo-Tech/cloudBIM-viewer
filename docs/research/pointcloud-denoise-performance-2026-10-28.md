# 双层钢筋柔性配准、分类与去噪性能排查（2026-10-28）

后续并行调度已更新为 `execution-v4`，最新完整 HTTP 实测为首次 63.75 秒、模型缓存命中后 53.77 秒，见[并行调度复测](pointcloud-denoise-parallel-2026-10-28.md)。以下保留本轮 `execution-v3` 的测量和取舍。

同一份 Lumos 扫描 14 / BIM 13、同一已保存配准，完整计算从修改前 **332.99 秒**降到最终本地 HTTP 首次运行 **73.61 秒**、模型缓存复用后 **63.50 秒**；主机直接调用复测为 **61.32 秒**。403.8 万个源点的类别、钢筋实例和场景实例逐行一致，导出源属性保持不变。**约 30 秒的目标仍未达到。** 本轮以实际完整计算和质量对照验收，不将更短的子步骤时长算作全流程完成。

## 为什么单楼板约 30 秒，双层却要数分钟

当前数据库保留的单楼板 5/7 结果为 3,900,373 点、27.28 秒；双层 14/13 的旧结果为 4,038,141 点、330.17 秒。点数只增加约 3.5%，不能解释十余倍耗时。历史单楼板与当前双层的执行内容不同：双层额外处理 422 个显式 IFC 夹具/预埋件/管段对象，执行短连接筋恢复、长筋柔性轴线拟合、端部弯钩复核和相容候选面补查。

“弯筋”阶段实际会检查 **48 个长筋设计单元、近 8000 个截面**，并对进入轴线拟合的单元比较四种模型。它不只是处理几段可见弯钩。端部弯钩另有一次随主体姿态更新而执行的复核。原实现还存在以下放大耗时的工作：

- 每个 IFC 构件独立创建几何求解器，丢弃可共享的解析状态。
- 每个夹具拟合都复制整场可用点云和法向量。
- 把已明确归类为夹具的 342 个产品也尝试作钢筋 BRep 圆截面解析，随后才删除。
- 密集截面投票重复作大量 Python 标量比较，支持点检查反复扫描整根筋的候选廊道。
- 四个独立轴线候选串行计算；相容备选面的 Python 遍历和三角形距离计算也占用大量时间。

本机为 Ryzen 7 9800X3D，8 核 / 16 线程；本地 mesh 容器未设置 Docker CPU 配额或内存上限。输入法向量已经复用，预处理约 1 秒。主要瓶颈位于上述 CPU 几何计算。

## 已实施的改动

1. IFC 使用一个共享几何 iterator，保持按 IFC ID 输出顺序；失败的产品保留单独诊断。仍逐对象验证完整 IFC→GLB→扫描坐标映射、边界和非对称参考点。其用法依据 [IfcOpenShell 官方几何 iterator 文档](https://docs.ifcopenshell.org/ifcopenshell/geometry_iterator.html)，并在本项目固定的 0.8.5 版本上实际验证。
2. 仅在存在显式 reinforcing 实体的语义场景中，提前跳过明确为夹具的 Plate/Member 钢筋圆截面解析。保留旧式 plate-only 钢筋导出和未明确归类的 proxy；缓存指纹包含提取模式。
3. 点云与法向量缓冲区只构造一次；独立构件姿态并行计算。原有几何阈值、独立验证和场景优先顺序保持不变。
4. 截面投票使用邻域标记代替重复逐中心比较；排序截面索引保留严格轴向窗口，并恢复源行顺序再划分训练/验证点。圆拟合使用解析 Jacobian；邻筋先验批量计算。
5. 同根筋的独立截面及四个候选轴线模型并行求解，按原顺序汇总；不同筋仍依次确认源行归属。只发送局部数组，限制排队副本与数值库线程数。
6. 增加小型 C++ 有限三角形/折线计算内核，保留稳定的等距选择规则、有限边界和法向门槛。Docker 多阶段构建负责编译，不新增 Python 依赖；无本地库时保留 NumPy 参考实现。未使用放宽浮点精度的编译选项。
7. 增加私有、按内容寻址的设计缓存。它只保存模型目录及已验证的设计几何，不缓存分类结果、扫描拟合姿态或点归属；每次应用当前完整配准矩阵。IFC/GLB 内容变化、读取器版本或提取约定变化均产生新条目。
8. 结果与后端响应新增可选 `stageTimingsSeconds`、`modelCacheHits`；版本标记为 `execution-v3`。旧结果仍可读取。

## 质量与数据保护

- **108 项 Python 测试通过**（完整回归 107 项，随后新增非有限法向量边界测试并重跑全部 5 项原生内核测试），覆盖原有钢筋/弯钩证据规则、真实进程池的串行/并行对照、长遮挡、邻筋竞争、源行排除、有限面匹配、任意刚体坐标、原生/NumPy 内核对照、缓存失效与完整逆变换。后端 `go test ./...` 通过。
- 最终主机复算的 `classes`、`instances`、`sceneInstances` 全部为 **0 个源行差异**；90 个物理设计父项、174 个匹配单元的完整设计几何和关系一致。实例和弯钩的确认状态、理由与点数一致；主体中心线最大差异为 0.179 微米，弯钩中心线差异小于 0.001 微米。设计数量不代表现场成功检测数量。
- 导出的 935,134 条钢筋记录，其所有原始 LAS 维度逐项等于对应源行；包括 XYZ、RGB、法向量、`source_index` 等，缩放、偏移、新增实例 ID 也已验证。
- 设计指纹因“提前排除夹具”的模式标记而有意变化。HTTP/Pydantic 还会把矩阵中的整数转为浮点数，旧 JSON 哈希区分 `0` 与 `0.0`。对照脚本对两端分别从输入内容和各自实际矩阵重算指纹，并额外检查完整数值矩阵及最终设计几何相等，不跳过来源校验。
- 实验使用独立输出目录，不发布新的业务 derivative，不改写原始数据、保存配准或旧结果。最终复核的 58 个关键文件哈希全部不变，数据库配准和 denoise derivative 记录也与任务开始快照一致，证据为 `preservation-final.json`。
- 已验证的是这一固定真实数据和所列算法回归。没有新增现场标注来证明绝对识别精度，也没有把 mesh API 时长当成浏览器点击到全部绘制完成的时间。

曾试验稀疏正规方程生成非线性求解初值。该版本为 58.55 秒，但有 2305 个类别字段发生变化，部分构件的独立支持率下降约 1.8 个百分点，因此已撤回，最终服务不含这段求解器。局部 KD-tree 裁剪也因增加实际耗时被撤回。相应实验记录保留用于解释取舍。
