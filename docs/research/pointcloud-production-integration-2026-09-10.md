# 整簇分割接入主应用

2026-09-10 按用户要求撤回最后的投影直线约束，将此前验证的整簇分割设为当前主应用默认算法。逐步调试继续作为练武场保留。

## 共用计算流程

`services/mesh-service/algorithms/pointcloud_segmentation.py` 提供 `segment_points`：法向量 → 法向几何与分层投影分类 → 融合与区域划分 → 空间整理 → 内部钢筋实例 → 外部钢筋整簇接续。生产和练武场都直接调用此入口。

- 生产适配器：`algorithms/rebar_geometric_v6.py`，算法 ID `geometric-v6`，版本 `1`。
- 练武场：`pointcloud_step_pipeline.py`，允许计算到 `throughStep=7`（页面第 06 步），负责保存中间数组、LAS、预览和投影图。
- 已撤回的最后直线约束不再注册、不再计算，也不再显示操作入口。原实验文档和历史产物仅作为记录保留。
- 默认算法在 Go 后端、Python API 和主应用面板中一致。旧版本仍可读，也可通过已有算法选择器回溯比较。

生产适配器读取全部有限源点，分块写入临时映射文件，调用共用流程，再把源点标签映射到已有显示瓦片。引导样本数量不会截断实际分类范围。当前上限为 2,000 万有限源点，超限返回明确资源错误；PLY/PCD 继续使用现有解码预算。生产分类不再应用旧 V5 的统计去噪。

分类编号显式转换：练武场的台面 1 / 夹具 2 / 钢筋 3 / 噪音 4，对应生产的台面 1 / 夹具 4 / 钢筋 2 / 噪音 3。钢筋实例编号、外部簇编号和分段编号保持原值；不对弯钩重新裁切。夹具本次统一分类，不再宣称识别方管、板和螺栓子类；理论交点能力关闭。

已验证的尺寸先验关联保持不变，使用同一源文件身份校验和 IFC 尺寸族读取逻辑。本轮不新增空间 BIM 先验接口。

## 练武场入口与后续迭代

独立服务继续运行于原来的 8766 端口，原 Host 白名单不变。主应用开发模式下提供“逐步调试 · 练武场”链接，明确使用独立调试样本。构建部署时可设置 `VITE_POINTCLOUD_WORKBENCH_URL` 指定可访问的调试地址；不会把主应用当前资产自动切换为调试源文件。
