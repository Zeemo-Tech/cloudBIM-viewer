# V5 分类去噪性能修复（2026-09-07）

后续内存复用优化和完整新进程验收见 [2026-09-08 验证记录](rebar-v5-performance-followup-2026-09-08.md)：921 万点完整发布为 719.13 秒；下文保留第一轮的测量及当时验证边界。

本次只优化已有几何算法的执行方式。参数、邻域半径、邻居数量、体素分辨率、全量特征、原始点支持验证及分类置信度公式保持原值。

## 已定位的问题

- `bolt_mask` 为每个螺栓对整个点块构造 shaft/head 格点元组，然后逐个执行 Python 集合查询。10 万个完全不相交的点、8 个模型，仍产生 160 万条 Python membership 记录。原始归属阶段会在支持邻域、核心点和最终分类中反复执行。
- `_consistent_fixture_normals` 对同一支持点集检查每个面时都重新构建 KD 树。20 个面对应 20 次完全重复的建树。
- `stage_features` 已有完整支持邻域的台面、夹具、螺栓掩码，却对核心点再算一遍。所有核心点都已属于台面或噪声时，仍执行没有边界更新输出的夹具计算。
- `SpatialStore.query` 对每个空间格子分别调用 NumPy 比较、归约。小核心多时，大量 Python 调用占用时间。
- 全量 PCA 的近邻查询原本只有一个线程；大批次可以用有限并行而不改变近邻结果。
- 真实夹具细化剖析暴露约 8.5 亿次调用。`sparse_grid_components` 为同一格子中的每个原始点重复查找并查集根，约 2.4 亿次 `find`；密集表面的 `_adaptive_grid` 还反复计算最终不会改变最小格子大小的完整近邻距离。

前端有重复点击保护，Go 有同资产计算锁，未发现重复提交。当前默认关闭全局归属复核；旧记录中该阶段耗时为零。`maxInputPoints=200000` 仅限制初始样本，不能限制 V5 的全量特征/标签工作。

## 修改

- 螺栓先按有限 shaft 和 **已观测 head 格点** 构造保守空间范围，再对相交候选执行原有精确条件。孔洞、cell 边界、头部实际观测范围仍由原格点决定。旋转或非正交坐标使用投影矩阵求逆；不稳定的坐标系保留精确路径。粗筛带浮点余量，最终阈值不放宽。
- 螺栓格点 membership 使用 NumPy 整数对操作，分类先排除与整个点块不相交的模型。
- 同一支持点集的面法向验证共享一个 PCA 上下文和 KD 树；空查询不建树。
- 按 `uint64 source_index` 从完整 halo 选择核心掩码。边界更新仍按台面、夹具顺序执行，并保留可供再次归属判定复用的稀疏更新文件。
- 空间格子 AABB 每批最多 4096 个，保留半开查询边界、源索引排序和内存上限。
- 连通分组每个已占用格子只解析一次根节点，用稳定分组映射回原始点；组件及组件内部点的顺序与旧实现完全一致。该共享函数也供 V4 使用，V4 回归纳入验证。
- 较大的密集表面先检查是否有严格多数点的正近邻距离小于 `base_grid/3`；满足时可证明原中位数公式必定返回最小格子大小。否则仍执行完整原算法。没有估计密度、改变格子大小或跳过稀疏区域。
- PCA 查询批次至少 1024 行时使用最多 4 个线程，并受 CPU affinity 数量约束；小查询保持单线程，BLAS 保持单线程。
- `fixtures` 阶段增加边界特征、提案、原始点细化、螺栓检测和掩码的分项计时，服务器日志显示提案和细化完成进度。
- 修复完整运行末尾的发布故障：螺栓 shaft/head 格点元组曾携带 `np.int64`，导致 JSON 序列化失败。生成格点时转为原生整数，数值和元组结构不变。新增检测器输出序列化及完整产物写入回归。

## 局部实测

同机、BLAS=1、三次测量取中位数。真实特征样本包含 281,507 个支持点和 141,753 个查询点。旧源码在修改前保存，比较时不加载变化中的实现。

| 工作 | 修改前 | 修改后 | 提速 |
|---|---:|---:|---:|
| 10 万远点 × 8 螺栓模型 | 0.371 s | 0.00749 s | 49.5 倍 |
| 真实点块全部多尺度特征 | 2.819 s | 1.758 s | 1.60 倍 |
| 同一真实支持集的 20 次面 PCA，包含建树 | 1.155 s | 0.108 s | 10.7 倍 |

全部局部结果逐数组精确相等；真实点块的 20 项特征均比较。局部提速不能直接当作整条流水线提速。
