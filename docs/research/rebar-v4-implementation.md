# 钢筋分割 v4：实现与验收记录

日期：2026-09-05。v4 为可选算法，默认仍使用 geometric-v3；没有真实逐点标注前，不将合成数据成绩描述为现场准确率。

## 问题与设计取舍

现有 v3 主要依赖两组水平直线和固定高度范围。近邻轴线合并、对平面边缘的误判、弯曲处切向变化、斜向连接筋和方管夹具均超出了这一模型的可靠范围。3D Hough 可以生成直线候选，但直线投票本身无法解决圆管/方管区分、弯钩实例连续性或接触处多归属。

v4 的边界是：从真实扫描证据提取钢筋；每根连续原材料钢筋及其弯钩共享实例 ID；交叉焊接不自动合并实例；台面与夹具/围挡分开；设计几何只提供经过配准与唯一性门控的辅助证据。完全不可见的设计钢筋不计作扫描识别结果。

## 接口和产物

- `RebarInputContext` 提供检测样本、可重复遍历的原始点块及转换到扫描坐标的可选 BIM 几何。
- LAS/LAZ 保留 source-reader-record 原始序号，逐块处理、逐块导出。PLY/PCD 当前 Open3D 解码仍需整体载入，不能声称读取内存有界。
- `scene_class`: 0 杂物，1 台面，2 钢筋，3 统计噪声，4 夹具/围挡。夹具不等同于台面。
- `rebar_flags`: bit 0 表示交叉；bit 1 表示实例归属不确定。已知胜者保留其 ID；真正不确定点用 `0xffffffff`，原始标签另存至少两个候选 ID。
- `labels/manifest.json` 和分块 NPZ 包含原始序号、全部属性、SHA256 和点数。候选归属采用稀疏 CSR，局部行号映射 NPZ 的 source_index。
- 展示瓦片点数与原始有限点数分开统计，避免用抽稀瓦片冒充完整数据评估。
- 前端通过实例中心线检查、单筋聚焦和夹具显隐帮助检查；设计推断段用虚线，实测段用实线。

## BIM 先验

后端仅接受 BIM asset ID，从同一用户的资产和已保存配准记录解析输入；客户端不能提交任意服务器路径。指纹覆盖模型、元数据、可用 IFC 内容、配准矩阵和提取器版本。v4 缓存还包含算法描述符。

IFC 提取不依赖 IfcReinforcingBar 语义，因为当前实际模型将钢筋放在 IfcPlate 中。支持圆截面拉伸、扫掠圆盘、折线/圆弧及映射实例；每个映射发生位置保留独立标识。毫米转换到米；column-major scan→BIM 矩阵取逆后返回原始扫描坐标。结合 GLB 检查导出坐标轴约定；未被 IFC 表达覆盖的产品才尝试保守 GLB 圆杆回退，避免重复。

保存的矩阵平移模长约 21.4mm 并不等于配准误差；由少量控制点得到的零 RMSE 也不是独立精度证明。实际匹配必须使用扫描残差和最近邻间距约束。

## 可重复验收

在 mesh-service 目录使用项目 Python 3.11 环境：

```bash
../../.cloudbim/mesh-venv/bin/python -m unittest test_rebar_validation test_rebar_stream test_rebar_bim
../../.cloudbim/mesh-venv/bin/python rebar_validation.py --algorithm both --output /tmp/rebar-validation.json
```

独立合成场景包含真实四平面方管、宽板、直径 8mm/中心距 16mm 与 22mm 的近邻钢筋、相切连续的 90°+180°扫掠钩筋、45°/60°连接筋和上下层交叉。几何断言验证方管平面、间距、弯管曲面和倾角。只有 24 个显式构造的交叉点排除在实例评分之外。

固定 seed 20260905，27,074 点，13 根真值钢筋：v3 基线钢筋点 precision 91.25%、recall 49.93%，夹具误判钢筋 22.16%，IoU≥0.5 实例召回 23.08%，钩筋点召回 36.27%，45°和60°斜杆召回均为 0。逐钢筋样例只报告召回，precision 在全场计算；同时报告夹具分类型泄漏和完整场景类别混淆矩阵。

## 研究来源

- [IPOL: Iterative Hough Transform for Line Detection in 3D Point Clouds](https://www.ipol.im/pub/art/2017/208/)：适合直线候选生成，不能单独完成弯曲实例和截面判别。
- [PCL Cylinder model segmentation](https://pointclouds.org/documentation/tutorials/cylinder_segmentation.html)：圆柱模型及法向约束是区分圆杆与平面的基础，但单侧稀疏扫描需要容许部分圆弧证据。
- [IfcOpenShell placement API](https://docs.ifcopenshell.org/autoapi/ifcopenshell/util/placement/index.html) 与 [unit API](https://docs.ifcopenshell.org/autoapi/ifcopenshell/util/unit/index.html)：放置、映射和单位处理。

## 最终验收结果

机器可读记录见 [rebar-v4-validation.json](rebar-v4-validation.json)。下表均为独立解析几何生成的合成场景，不代表真实工程准确率。

| 场景 | 钢筋点 precision / recall | 夹具→钢筋误判 | 实例 IoU≥0.5 precision / recall | 钩筋归属一致性 |
|---|---:|---:|---:|---:|
| seed 20260905，单侧表面 | 99.965% / 99.442% | 0% | 100% / 100% | 100% |
| seed 20260906，单侧表面 | 99.991% / 99.185% | 0% | 92.857% / 100% | 97.251% |
| seed 20260907，单侧表面 | 99.957% / 99.382% | 0% | 92.857% / 100% | 98.989% |
| seed 20260905，完整圆周 | 99.948% / 98.515% | 0% | 92.857% / 100% | 100% |

主场景 13 根真值对应 13 个实例，没有合并或拆分；其余三组存在一个额外小片段，因此没有只报告召回而隐去实例 precision。另加入了独立审查提出的直径 5mm、中心距 8mm 的三筋反例，修复后分别识别为三个实例，各根正确归属点比例超过 98%。这是可分辨输入下的验证，不能外推到扫描分辨率以下的间隙。

实际 9,216,369 点 LAS：最终离线全流程 106.71 秒，峰值 RSS 680.80 MiB；空间覆盖采用 4.725mm 体素保留 209,804 个检测点，然后完整遍历原始点统计支持并导出标签。93 个原始标签块的 SHA256、连续 source index、候选 CSR、类别和实例 ID 全部通过核验。展示瓦片为 2,302,885 点，单独统计。

真实原始标签统计：台面 5,113,834，夹具/围挡 1,510,213，钢筋 1,904,958，杂物 687,364；126,808 点保留不确定实例归属及候选列表。算法产生 174 个候选实例，**这个数字不能当作现场钢筋根数**：真实数据没有逐根真值，而且遮挡处仍会分段。当前设计几何提取 56 根候选（50 IFC + 6 GLB 回退），通过正式后端读取已保存配准后，唯一匹配 15 个扫描实例；96 个扫描实例匹配不够唯一而保持几何结果，本次没有强行使用设计连接。BIM 单元测试另外验证了唯一片段合并、20mm 不确定度、错误方向和竞争拒绝。

正式后端计算耗时 103.80 秒，产物版本 `1788606073985250036-d081d487de24` 已保存到扫描资产 5。最新结果接口、原始标签接口、重复请求缓存均通过；正式产物原始点分类与离线验收一致。基于正式接口的浏览器检查通过中心线、夹具显隐、单根聚焦，加载了 174 个候选选项，没有 page error。离线性能记录使用近似矩阵，仅用于几何与资源验收；实际 BIM 关联以正式后端保存的矩阵为准。

最终检查包括 94 项 rebar Python 测试、完整 Go 测试、3 项可视化 Node 测试、Vue 类型检查与生产构建。Host IfcOpenShell 因主机 Conda 的 sqlite 动态库打印可选 SQL 支持警告，但 IFC 解析测试通过；同一提取在项目容器中没有该警告。前端构建仅有既有大包体积提示。

## 审查后的修正

1. 近邻合并阈值改为与估计半径关联；长轴重拟合后再次检查横截面空隙，避免小直径三筋整束落入“大圆柱允许半径”。
2. 点投影会自适应扩大已饱和的邻域，直至覆盖可能竞争的其他实例；候选矩阵分批，避免短片段集中时漏掉第二实例或扩大内存峰值。
3. 方管面检测增加台面法向作为候选方向，但每个面仍须通过独立平面核心、有限矩形、宽度和二维占据率验证。
4. 重叠实测片段不再产生假缺口；原语间缺口如果缺少唯一、切线连续的支持，保守记录为 geometric-gap。附近存在一些点并不等于本根钢筋的连续实测证据。
5. 空输入与非法矩阵给出明确错误；全台面输入返回合法空实例结果。

## 使用、回退与剩余限制

本地预览的钢筋面板提供 `Geometric rebar v4 (experimental)`，可使用已有 BIM 配准、查看实测中心线、聚焦单根、隐藏夹具/围挡。虚线包含几何或 BIM 推断连接，均不计为原始扫描实测点。截图中的斜杆按任意三维方向检测；从图像形状看可能是桁架腹杆或上下层连接筋，不能仅凭该图确认每一根都是运输吊环。

默认计算算法保持 v3；v4 结果可以单独选择和检查。原有真实 v3 产物已保存在本机 `.cloudbim/rebar-v3-baseline/`，避免重算覆盖后失去对照。

- 实际检测仍会受点间距、噪声、单侧表面及焊接接触影响。真实数据中仍有实例碎片；未宣称实现了现场精确计数。
- 完整圆周场景的 60°短斜杆点召回约 79.83%，虽然实例仍被识别；这是需要后续真实标注检验的薄弱项。
- 几何缺口可以保留同一实例并显示虚线，但不能借此声称弯曲位置完全被扫描观测。更强的弯曲恢复需要切向连续、截面稳定及唯一点归属共同支持。
- 半径通过局部截面紧致度估计；平面核心和占据率用于拒绝方管/板面。当前没有严格的带肋钢筋物理表面拟合或学习模型。
- 原始点完整参与最终投影与支持统计，但检测几何来自空间覆盖点，并非对九百万点逐点进行圆柱优化。
- 20mm 设计先验不确定度下，相邻候选若无法唯一匹配则拒绝关联，完全不可见的设计钢筋不会被“补识别”。

下一步推广为默认算法前，应在真实扫描上标注近邻、边框、弯钩和斜杆的逐点类别/实例，按独立空间区域验收 precision、recall、实例 IoU、合并/拆分和运行时间。当前版本适合并列试用与人工核验。
