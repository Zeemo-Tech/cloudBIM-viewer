## 实现

- `PointBoundsIndex` 为每个查询块建立三轴排序索引，按候选数量最少的坐标范围查询，再做原有精确几何判断。索引只返回升序源行；最多保留 48 字节/点，预算为 64 MiB，超预算采用原位范围扫描。
- 夹具逐面分类使用稀疏行数组，消除每个面都重新扫描/分配整个点块布尔掩码的工作。最终距离、占用格点、边界、置信度和同分裁决保持原运算。
- 螺栓逐点归属使用已有保守 AABB 与相同点索引，奇异或病态投影仍走完整候选回退。
- 二维占用格点在坐标均落于 int32 范围时使用无碰撞 uint64 拼接键查询；更宽整数及非整数模型数据保留 tuple 相等语义。
- 原有 132 个 core 的去噪和基础特征任务按内存预算并行；夹具完整区域任务使用 spawn 进程，结果按原顺序收集。缓存及产物写入仍由主线程负责。
- 并行上限由 `REBAR_SPATIAL_WORKERS` 控制，默认为 4，1 可退回串行。有效数量同时受 CPU affinity、各级 cgroup CPU 配额、主机可用内存、各级 cgroup 剩余内存、8 GiB RSS 余量及未用缓存预算约束。为每个任务预估支持点、PCA 临时数组、返回列和进程导入空间，并额外预留 2 GiB；内存未知或不足时串行。
- 有界队列最多保留与 worker 数相同的任务及结果。每个原始点仍只由原 core 输出一次；halo 不输出点，没有修改 core/halo 边界或树中点的顺序。

## core 合并的已验证限制

一个真实相邻块扩大支持范围后，119,327 个查询点的特征仍精确相同；但这不能证明合并对所有点云都安全。使用默认 64 邻居参数构造 67 个等距支持点，再加入 100 个查询半径外的点，KD-tree 的等距截断顺序改变，输出法向与切向也改变。重现脚本为 `.cloudbim/denoise-performance/speed/probe-halo-ties.py`。因此本轮不扩大/合并 PCA 索引的支持集合，保留原 132 个 core，以有界并行消除串行调度瓶颈。未来若合并，需要解决既有等距邻居顺序兼容性，不能仅凭半径内几何集合相同宣布精确等价。
