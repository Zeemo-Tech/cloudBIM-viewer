# 设计先验辅助钢筋分类：练武场试验

> 历史记录：下文为旧 IFC / v2 试验，其“找回待定候选”规则造成用户反馈的退化，已经停用。当前实现、替换 IFC 的正确提取及多视角复核见 [第二轮：只串联最终保留簇](pointcloud-design-prior-linking-review-2026-09-10.md)。本文件的旧性能、动作和数量不代表当前结果。

本轮已实现模型提取、服务端先验快照、几何/拓扑复核、独立导出和练武场对比。新增步骤位于原有整簇接续之后，`priorMode` 默认 `off`，生产流程继续使用原有结果。性能通过与精度通过是两个独立条件；没有人工真值时，质量验收保持 `unverified`。

## 当前模型及坐标约定

本次源点云共 9,216,369 点，SHA-256 为 `eb229b7c514e918c03534184eb56ceabdfd850c57b1b3503172bd8f290ebab52`。使用现有 `YB-1.ifc`，以及 scan asset 5 / BIM asset 4 已保存的粗配准矩阵；不需要等待新的钢筋族 IFC。

当前 IFC 将钢筋以 `IfcPlate` 和映射几何导出，不能把 IFC 产品数量直接当成物理钢筋数量。按映射出现位置展开后，本轮识别 70 个几何对象：56 个完整直筋、10 个带弯钩长筋的可靠直线主体、4 个未能解析中心线的复杂对象。得到 66 个匹配单元，其中 12 个短筋单元的设计长度为 280 mm，另有 54 个普通直线单元。这 12 根只作为提取核对基准，不作为点云的强制数量配额。

当前复杂腹杆没有可靠的设计斜段提取结果，因此“已解析设计斜段数”为 0。它不表示实际没有腹杆。本轮对这些观测腹杆保留原有斜段实例和待定状态，不将其强配给水平筋，也不根据设计整根数量进行合并。

坐标处理顺序为 IFC 单位转米 → 校验 IFC/GLB 轴系 → 应用已保存 `scanToBim` 的逆变换，得到原始扫描坐标。浏览器只在显示时减去预览原点；LAS、NPY 和匹配 JSON 中的实测点不移动。当前 IFC 到 GLB 的轴系为 `(x, z, -y)`。

## 身份与复核规则

| 对象 | 标识与用途 |
| --- | --- |
| 设计整根 | `designBarId`，用于追溯 IFC 几何出现位置、分组及拓扑展示 |
| 匹配单元 | `designUnitId`，普通直筋一个单元，连续折弯筋按可靠直线段拆分，记录 `ordinal` 和 `next` 邻接关系 |
| 观测实例 | `prior_instance`，每个腹杆斜向保持独立编号；同一设计父编号不授权合并 |
| 复核组件 | `prior_component`，内部实例的连通片段或不可拆分的外部整簇 |

每个单元保存中心线、方向、直径、可用长度、层位、来源、可信程度与覆盖程度。局部关系包含平行相邻的相对偏移、水平交叉的上下关系，以及同一设计整根内部的斜段顺序。夹具分区复用扫描中已识别的内外框，将单元穿过的观测分区写入 `observedFixtureZones`；当前 IFC 未提供可靠夹具语义，不能把所有 `IfcPlate` 解释成夹具。

先用实测点、已计算法向量和已有圆柱拟合支持判断钢筋几何，再生成最多 16 个设计候选。一般横向搜索范围为 150 mm，短筋为 350 mm，覆盖本样本跨一个相邻间距的偏位；位置、长度和直径只进入软评分。拓扑模式最多进行两轮局部复核，不使用全局图优化或数量配额。

合并要求匹配单元相同、实测轴向连续、横向偏差不超过 4 mm、轴向间隙不超过 30 mm、方向偏差不超过 8°，且不存在超过 5 mm 的轴向重叠。合并来源和目标实例的相关组件均须有一致对应，夹带待定或其他单元支持的实例不合并。相邻腹杆斜段接触时仍保留各自编号。

只有几何证据弱、小于 15 mm、明显非线性，并且缺乏邻近实测钢筋支持的组件才自动过滤。接续支持覆盖整段实测轴线，避免长筋中部的小碎片因远离端点和中点而被误删。不能仅因远离设计、长度不足或数量超额过滤。证据不足的外部候选保留为待定，可能使显示中的候选点增加；“找回”是处理动作，不等于已证明是真实钢筋。

超过 30,000 个复核组件或没有可靠设计单元时，复核降级为保留原结果。早期归为台面、夹具的点不进入本轮复核。模型变化使模型和对齐缓存失效；仅改变粗配准矩阵只重建对齐缓存。源路径与 SHA-256 必须同时匹配，错误快照拒绝运行。

## 练武场操作与输出

入口为现有 [8766 练武场](http://10.0.0.4:8766/)。在“重新运行”中选择关闭、几何先验或几何 + 拓扑先验；增强要求完整执行到原流程第 7 步。结果中新增“07 设计先验复核”，可切换基线/增强、设计线、短筋及过滤/恢复/合并/待定筛选。默认显示增强钢筋结果。

“观测实例”按斜段实例着色；“设计母筋分组”只切换颜色和展示分组，不改变点云实例编号。当前未解析腹杆对应保持待定。旧历史结果没有先验属性时，新增控制自动停用。

增强结果独立保存 `design-prior.json`、`prior-steel.las`、`prior-noise.las` 和五列 NPY/预览属性。全量 LAS 同时保留原始字段、原有步骤属性及新属性。

| 属性 | 说明 |
| --- | --- |
| `prior_class` | 1 台面、2 夹具、3 钢筋候选、4 噪声；待定候选仍为 3 |
| `prior_instance` | 观测实例编号；0 表示未分配，不代表这些点属于同一根筋 |
| `prior_component` | 本次复核组件编号，0 表示不在复核范围 |
| `prior_status` | 0 范围外、1 已匹配、2 待定、3 噪声 |
| `prior_action` | 位标志：1 本次过滤、2 本次找回、4 实例合并 |

组件 JSON 保存原实例、设计父/单元对应、候选列表、实测直径与长度、几何证据、动作及原因。`source_record_index` 始终对应源 LAS 行；设计中心线不会代替实测坐标或补造遮挡点。

服务端配置位于忽略目录 `.cloudbim/design-prior/config.json`，包含 `sourcePath`、`sourceSha256`、`ifcPath`、可选 `modelPath` 和列主序 4×4 的 `scanToBim`。相对路径相对于配置文件目录解析。浏览器 `/api/run` 仅接受 `k`、`workers`、`throughStep` 和 `priorMode`，不能提交模型路径、矩阵或先验快照。获得新的钢筋族 IFC 后更新服务端配置，下一次运行按相同接口重新提取。

练武场是独立调试进程，不替代 `scripts/cloudbim-dev.sh` 管理的主应用栈。当前监听 8766，启动命令在仓库根目录执行：

```bash
.cloudbim/mesh-venv/bin/python scripts/pointcloud-debug.py \
  --source backend/data/assets/95b6b41c5857d9eb3407b155/source.las \
  --output backend/data/assets/95b6b41c5857d9eb3407b155/pointcloud-steps \
  --host 0.0.0.0 --port 8766 --allow-host 10.0.0.4 \
  --workers 16 --through-step 7 \
  --prior-config .cloudbim/design-prior/config.json
```

## 性能与质量验收

最终算法版本为 `design-prior-refinement-v2`。下表来自最终版本的九次独立进程运行。

| 模式 | 全流程中位数 | 相对 A | CPU 中位数 | 峰值 RSS 中位数 | 复核本身中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A 原流程 | 18.996 s | — | 137.024 s | 2711.0 MiB | 0.000 s |
| B 几何先验 | 20.034 s | +5.47% | 139.897 s | 2886.3 MiB | 0.541 s |
| C 几何 + 拓扑 | 20.103 s | +5.83% | 140.310 s | 2879.5 MiB | 0.592 s |

两种增强模式均通过 20% 增量墙钟时间门槛。包含 Python 启动、缓存读取及进程退出的总耗时中位数分别为 19.425 / 20.534 / 20.633 s，也均在预算内。

两种增强模式均有 1,293 个复核组件、5 个判噪组件，本次新过滤 193 点、保留原先过滤的 64,478 点，实例合并为 0。B 为 221 个匹配、1,067 个待定；C 为 305 个匹配、983 个待定。这些是算法动作统计，匹配增加或保留点增加均不能证明准确率提高。质量门槛仍为 `unverified`，未进入正式流程。

最终完整记录见 `docs/research/assets/pointcloud-design-prior-benchmark-2026-09-10.json`；本机复核模板和文件验证记录分别位于 `.cloudbim/design-prior/final/review-set.json`、`.cloudbim/design-prior/final/artifact-validation.json`。

最终第三轮结果：

- off: `20260910T053652-a65e5f74`
- geometry: `20260910T053712-56a89d70`
- topology: `20260910T053733-a2c942c9`


每种模式各运行三次，顺序为 A/B/C、A/B/C、A/B/C，固定相同源文件、机器和 16 个工作线程，每次启动独立进程。全流程墙钟时间包含读取、分类、复核以及全部 LAS/NPY/预览/JSON 导出；另记进程启动到退出耗时、全流程 CPU 时间和独立进程峰值 RSS。没有清空操作系统文件缓存，首次模型提取单列，不混入在线比较。

第一轮冷模型提取为 0.686 s，含对齐清单生成共 0.722 s。模型和对齐缓存命中后的准备时间为毫秒级。`performance.cpuS` 已修正为全流程 CPU 时间，法向计算自己的统计保存在 `normalComputation`，避免把法向计算耗时误报为完整流程耗时。

人工复核模板包含全部 12 个短筋设计区域及腹杆、交叉、夹具/弯钩、离散噪声候选区域；短筋窗口扩展 350 mm，避免只看设计附近而漏掉偏位筋。窗口选择基于不变的组件几何和原有类别，不依赖 B/C 是否匹配，确保两组使用相同复核集。区域只是定位线索，须人工确认是否覆盖目标现象。

模板中的组件初始均为 `unknown`。填写 `reviewedBy`、区域的 `reviewed: true`，以及组件 `label: steel/noise/unknown`；短筋额外标为 `category: short`。钢筋真值 `truthInstanceId` 必须是观测钢筋编号，腹杆按每个斜向单独编号，不能使用设计整根 ID。无法判断或混杂的组件保留 `unknown`，不按设计数量推导标签。

评分比较真实钢筋保留率、真实短筋保留率、噪声误保留率、实例分裂和误合并，并按人工类别单列待定点数。缺少标签、实例真值或未完成固定区域复核时，不允许通过质量门槛。保留率按复核点数加权；结果只代表人工标注范围，不能外推为整幅点云准确率。只有噪声或分裂改善、钢筋和短筋保留率不下降、误合并不增加，且满足耗时预算，才具备后续进入正式流程的条件。脚本本身不会自动启用生产。

复现实验：

```bash
.cloudbim/mesh-venv/bin/python scripts/pointcloud-design-prior-benchmark.py \
  --config .cloudbim/design-prior/config.json \
  --output backend/data/assets/95b6b41c5857d9eb3407b155/pointcloud-steps \
  --report .cloudbim/design-prior/final/benchmark.json --workers 16 --rounds 3
```

人工标注完成后用 `--evaluate-only --annotations .cloudbim/design-prior/final/review-set.json` 加到上述命令末尾即可对现有文件评分，无须重新运行九次。重复基准会另建复核模板，不覆盖已有人工标注。模板绑定源文件、组件指纹和设计快照，过期标签拒绝评分。

## 验证与代码位置

- `services/mesh-service/rebar_design_prior.py`：模型提取、匹配单元和两级缓存。
- `services/mesh-service/algorithms/design_prior_refinement.py`：几何证据、局部匹配、保守过滤和同单元合并。
- `services/mesh-service/pointcloud_step_pipeline.py`：练武场可选步骤、保留旧属性的导出。
- `scripts/pointcloud-debug.py` 与 `scripts/pointcloud-debug/`：服务端配置和页面对比。
- `scripts/pointcloud-design-prior-benchmark.py`：交替独立进程基准、固定复核集和质量门槛。
- `scripts/pointcloud-design-prior-check.py`：全量源字段、坐标、旧属性、唯一归属及导出一致性校验。

专项测试覆盖一根设计腹杆六个单元/六个观测实例、缺失斜段、同斜段碎片合并、相邻斜段不合并、并排/重叠支持冲突、带待定片段的合并目标、长筋中段邻近小碎片保护、短筋跨间距偏位、实测直径差异、模型缺项和两级缓存失效。端到端小样本测试核对 LAS/NPY/预览与源坐标一致，接口测试检查默认关闭及客户端不能注入先验。

最终相关 Python 检查通过 100 项（算法、生产兼容及导出 89 项，调试接口和复核评分 11 项）。实际点云的 B/C 全量文件验证均通过：原有 29 列属性逐元素一致，9,216,369 个源点的字段和坐标不变，384 个外部簇完整归类，147 个观测腹杆斜段编号保持独立；LAS/NPY/百万点预览及子集一致。

真实百万点预览也通过 Node/Three 页面辅助函数检查，练武场页面、脚本、状态及最终结果通过 HTTP 检查。当前环境没有可用的 CUA 浏览器，因此没有将函数检查与 HTTP 检查描述成真实浏览器交互验收。
